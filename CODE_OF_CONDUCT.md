# Code of Conduct

## The short version

Be decent. Assume the other person is trying to help. Argue about the code, not
about the person writing it.

## What's expected

- **Critique code, not people.** "This leaks a file handle on the error path" is
  useful. "This is amateur work" is not, and it is also less specific.
- **Assume competence and good faith.** People arrive with different backgrounds,
  hardware, and languages. A question that seems obvious to you was not obvious
  to them, and answering it is cheaper than the argument about whether they
  should have asked.
- **Disagree in the open, then let it go.** Technical disagreement is how the
  code gets better. Re-litigating a settled decision across five threads is not.
- **Respect the "no".** Not every feature belongs in this project. A declined PR
  is a decision about scope, not a judgement of you.

## What's not

Harassment, personal attacks, or demeaning comments — including about someone's
experience level, nationality, gender, sexuality, disability, religion, or
appearance. Sexualised language or imagery. Deliberate misgendering or
dead-naming. Publishing someone's private information. Sustained disruption of
discussion.

Two specific to this project, because of what it is:

- **Do not post other people's footage, faces, or number plates** in an issue,
  a PR, or a discussion. Redact them, or describe the problem in words. Someone
  in a video frame did not consent to appearing in a bug report.
- **Do not publicly post a working exploit** for an unfixed vulnerability. That
  is not research in the open, it is handing it to whoever reads next. See
  [SECURITY.md](SECURITY.md) for the private route.

## Scope

Applies in the repository — issues, pull requests, discussions, commit messages,
code comments — and anywhere someone is representing this project.

## Enforcement

Report it through
[GitHub's private reporting](https://github.com/anivarhq/anivar/security/advisories/new)
if it involves anything you would not want public, or open an issue if it does
not.

This is a small project with one maintainer, so the honest answer about process:
reports get read and acted on, but there is no committee and no appeals board.
Responses run from "please stop" to an edit, to a block. Serious or repeated
behaviour goes straight to a block without the warning.

Reports are handled privately. Reporting something in good faith will not be held
against you, even if the outcome is that nothing was wrong.
